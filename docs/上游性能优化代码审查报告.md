## 三、必须修的问题（P1）

### 1. 录像后台线程异常会让"停止并保存"永久卡住

**位置**：`analysis_service.py` → `_FrameRecorder._drain()` 与 `close()`

**问题**：`_drain()` 没有 `except`。如果 `VideoWriter.write()` 抛异常（磁盘满、编码器错误、文件被占用），后台线程直接退出；而 `close()` 里的 `queue.join()` 会**永远等待**未被消费的队列项，导致 `stop_realtime()` 卡死，训练记录保存不了。

**建议改法**：

```python
def _drain(self):
    while True:
        item = self._queue.get()
        try:
            if item is None:
                return
            if self._failed:
                continue
            try:
                self._writer.write(item)
            except Exception as exc:
                self._failed = True
                print(f"[录像] 写盘失败，后续帧丢弃: {exc}")
        finally:
            self._queue.task_done()

def close(self, timeout=10):
    try:
        self._queue.put_nowait(None) if self._failed else None
        if self._failed:
            # 失败时不再 join，直接清空队列
            while not self._queue.empty():
                self._queue.get_nowait(); self._queue.task_done()
        self._queue.join()
        self._thread.join(timeout=timeout)
    finally:
        self._writer.release()
    return self._dropped
```

### 2. `stop_realtime()` 阻塞事件循环

**位置**：`main.py` → WebSocket `finally` 分支

**问题**：`final = service.stop_realtime()` 是同步调用，而新的 `close()` 会 `join` 后台线程（最多 10 秒），会卡住整个事件循环，其他用户请求全部变慢。

**建议改法**：

```python
final = await run_in_threadpool(service.stop_realtime)
```

### 3. `half` 参数已被 Ultralytics 废弃

**位置**：`analyzer.py` → `self.pose_model(..., half=self.half)`

**实测警告**：

```
WARNING 'half' is deprecated and will be removed in the future. Use 'quantize' instead.
```

**问题**：Ultralytics 8.4.x 已把 `half` 改为 `quantize`（16=FP16、8=INT8、32/None=FP32）；当前只是警告，未来版本会直接报错。另外本机是 CPU 版 torch（`torch 2.13.0+cpu`、`cuda_available False`），`half=False` 也会触发该警告。

**建议改法**：

```python
predict_kwargs = dict(imgsz=POSE_IMGSZ, conf=POSE_CONF, device=self.device, verbose=False)
if torch.cuda.is_available() and self.device != "cpu":
    predict_kwargs["quantize"] = 16     # 或先验证 quantize 是否被当前版本接受
results = self.pose_model(frame, **predict_kwargs)
```

并建议在 `requirements.txt` 锁定 ultralytics 版本，避免升级后参数失效。

## 四、需要评估/验证的问题（P2）

### 4. 排球检测抽帧只在单段素材上验证过

- 实测 150 帧素材 interval=1 与 interval=2 结果一致；
- 但抽帧帧不更新球轨迹，`_predict_volleyball_position()` 在只有 1 条历史时返回 `None`；
- 低帧率、快速球、多人遮挡时可能出现"动作区间被提前截断"。
- **建议**：视频（离线）分析默认 `VB_BALL_INTERVAL=1`，实时分析用 2；用 5–10 段不同素材做对比实验（动作数、平均分差异 < 5% 才可接受）。

### 5. 非 JSON 文本会中断实时会话

`main.py` 里 `json.loads(message.get("text") or "{}")` 没有 try/except，客户端发一条非 JSON 文本就会让整个会话结束。建议加保护并回一条错误消息。

### 6. 上游把测试文件合并进了 main

`docs/PR连接测试.md` 是临时测试产物，已被合并到 main。建议开一个清理提交删除它。

### 7. 后端仍用 JSON+base64 回传帧

只有"浏览器→后端"改成了二进制，"后端→浏览器"仍是 base64 JSON（体积约多 33%）。属于可继续优化项，不影响正确性。

### 8. 线程池 + `_rt_lock` 缺少后端侧背压

前端有 `camSendBusy` 控制单帧在途，但后端没有防御：若有客户端不做背压，任务会在线程池排队、延迟累积。建议加信号量或"在途帧数"上限。

### 9. `dropped_frames` 未展示

后端已统计丢帧数并写入 summary，前端实时结果里没有显示。建议加一行"录制丢帧：N"。

### 10. 文档未同步

`README.md` 没有说明 `VB_DEVICE`、`VB_BALL_INTERVAL`、`VB_POSE_IMGSZ` 等环境变量，建议补充。
