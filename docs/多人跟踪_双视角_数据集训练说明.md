## 一、多人跟踪 ID（初步实现）

### 1. 解决的问题
原系统只分析“第一个人/置信度最高的人”，多人同时出现时会丢失其他运动员信息，也无法区分不同学生。

### 2. 实现方式

- 跟踪器：`tracking.py` 中的 `SimpleTracker`，基于边界框 IoU 的贪心匹配；
- 每人分配稳定 ID：`ID:1`、`ID:2` …，连续帧保持；
- 丢失容忍：目标短暂消失 30 帧内仍保留 ID；
- 主分析对象选择优先级：
  1. 延续上一帧的主分析 ID（保持连续性）；
  2. 离排球最近的人；
  3. 画面中面积最大（通常离镜头最近）的人。
- 画面显示：每个人物框上标注 `ID:n`，主分析对象用黄色标注 `(主)`；
- 数据记录：每个动作回次保存 `person_id`，训练结果返回 `max_person_count`、`avg_person_count`、`primary_ids`。

### 3. 实测结果
- 跟踪器单元测试：两帧两人位置轻微移动，ID 稳定保持 `[1,2] → [1,2]`；
- 视频分析返回：`primary_ids: [1]`、`max_person_count: 1`（测试视频为单人）。

### 4. 当前局限
- 是 IoU 跟踪，不是深度 ReID；长时间遮挡或换人后可能重新分配 ID；
- 尚未识别具体学生身份（需要人脸/号码/绑定学生账号才能做到“人到人”）；
- 学生端只会分析主目标，其他运动员仅做展示。

## 二、双视角几何校正（初步实现）

### 1. 单视角透视校正

- 模块：`geometry.py`
- 原理：教练在标定页标记场地四角 → 计算图像到场地平面(9m×18m)的单应矩阵 H；
- 用 H 估计每个位置的局部像素尺度（米/像素），对关键点垂直方向做比例补偿，减小“近大远小”对关节角度的影响；
- 分析时选择 `视角A / 视角B` 标定即可启用。

实测（合成标定点）：

| 位置 | 局部尺度（米/像素） |
| ---- | ---- |
| 近处（画面下方） | 0.0220 |
| 远处（画面上方） | 0.0449 |

可见透视导致的尺度差异接近 2 倍，校正后关键点坐标发生变化。

### 2. 双视角融合

- 接口：`POST /api/analyze/dual`（两路视频 + 两个标定标签）；
- 页面：练习分析 → 视频分析 → 勾选“双视角融合”，分别上传两台摄像机的同步视频；
- 融合方式：两路视频分别分析，按动作序号对齐，分数取平均、反馈取并集、达标以平均分 ≥ 80 判断；
- 结果保存为一条 `mode=dual_view_fusion` 的训练记录，包含两路分析摘要。

### 3. 当前局限
- 是“结果级融合 + 单应尺度补偿”，不是完整的双目标定/三角测量三维重建；
- 要求两路视频近似同步、动作顺序一致；
- 若场地四角标定不准，校正效果会变差。

## 三、数据集管理与模型重训（初步实现）

### 1. 数据集管理

教练端 → “🧪 数据集与训练”：

- 新建数据集（任务：目标检测 detect / 姿态估计 pose）；
- 上传图片，可同时上传同名 `.txt` 标签文件（YOLO 格式）；
- 查看数据集数据量、删除数据集。

数据存放：`data/datasets/<数据集ID>/images`、`labels`。

### 2. 模型训练

- 选择数据集 → “开始训练” → 填写 epochs / 基础模型 / imgsz / batch；
- 后端自动生成 `data.yaml`，在后台线程启动 Ultralytics YOLO 训练；
- 训练日志保存到 `data/datasets/<ID>/train_job_<任务ID>.log`；
- 权重复制到 `models/trained/job_<任务ID>/best.pt`；
- 任务状态：`running / success / failed / finished_no_weight`。

### 3. 启用新模型

- 训练成功后点击“启用模型”；
- 系统自动备份当前生产权重为 `pose_best_before_<任务ID>.pt` / `best_before_<任务ID>.pt`；
- 再复制新权重为 `pose_best.pt` / `best.pt`，重启服务后生效。

### 4. 实测结果
- 数据集创建接口：200；
- 训练任务启动接口：200，任务 ID 正常生成；
- 空数据集训练会按预期失败并记录错误日志（说明训练链路和错误反馈正常）。

### 5. 当前局限
- 没有内置标注界面，标签需用外部工具（LabelImg / LabelMe / Roboflow）生成 YOLO 格式；
- 训练在服务器上运行，CPU 训练较慢，建议使用 NVIDIA GPU；
- 训练完成后必须先用测试视频验证，再“启用模型”。
