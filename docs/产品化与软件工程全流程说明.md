## 一、需求分析

### 1. 用户与场景

| 角色 | 场景 | 核心诉求 |
| ---- | ---- | ---- |
| 学生 | 课后自主练习、课堂训练 | 知道自己哪里不标准、如何改进、有没有进步 |
| 教练 | 课堂教学、队伍训练 | 同时关注多人、留下训练数据、快速看到共性问题 |
| 项目验收方 | 大创结题、系统演示 | 功能完整、可现场运行、可量化展示 |

### 2. 功能需求

- 动作识别与评分：垫球、发球、传球、扣球；
- 输入方式：图片、视频、摄像头实时；
- 标准动作库：教练上传示范视频、维护标准参数；
- 偏差反馈：把角度偏差转成自然语言建议；
- 训练记录：保存每次训练得分、动作数、标准数、反馈；
- 报表统计：规范率、平均分、常见问题；
- 实时分析：摄像头实时评分、计数、反馈、录制、落库；
- 标准学习：慢放、关键帧；
- 视角标定：记录场地基准点。

### 3. 非功能需求

- 可离线运行：本地 Python 服务 + 浏览器，不依赖云端；
- 可在普通笔记本运行：轻量模型 + CPU 可跑；
- 数据本地化：SQLite 存储，便于备份与展示；
- 易部署：一条启动命令 / 一个 bat 脚本；
- 可用性：中文界面、按钮明确、错误提示可读。

## 二、架构设计

### 1. 分层架构

```text
┌─────────────────────────────┐
│ 表现层 index.html + JS      │  学生端 / 教练端页面、实时面板
├─────────────────────────────┤
│ 接口层 main.py (FastAPI)    │  REST + WebSocket + 静态资源
├─────────────────────────────┤
│ 业务层 analysis_service.py  │  视频分析 / 实时会话 / 落库编排
├─────────────────────────────┤
│ 算法层 analyzer.py          │  动作区间状态机、排球追踪
│   body.py / pose_judge.py   │  姿态估计、评分与反馈
│   volleyball_detect.py      │  排球检测
├─────────────────────────────┤
│ 数据层 storage.py (SQLite)  │  标准动作、训练记录、回次、标定
└─────────────────────────────┘
```

### 2. 关键设计决策

- 采用“浏览器 + 本地服务”而不是纯桌面程序：复用现有半成品、跨平台、便于演示；
- 模型与业务解耦：`MLManager` 思想的简化落地，模型权重可替换；
- 训练记录结构化：session（一次训练）+ attempt（一次动作）两级模型，支撑报表；
- 标准参数数据化：阈值存数据库，教练可在 UI 调整，无需改代码；
- 实时分析有状态会话：开始/帧处理/停止三阶段，停止时统一汇总与落库；
- 输出视频使用 WebM：解决 MP4(MPEG-4) 浏览器不兼容问题。

## 三、开发与测试

### 1. 开发过程

1. 需求梳理：从项目计划书提取 8 项功能要求；
2. 原型评估：对比旧半成品（Web + YOLO）与 volleyball_analytics（比赛分析框架）；
3. 架构设计：保留旧半成品的视觉引擎，新增数据层、标准库、角色页面、实时模块；
4. 增量开发：数据层 → 后端接口 → 前端双角色 → 实时分析；
5. 回归验证：图片 / 视频 / 实时三条链路分别测试。

### 2. 已完成的测试记录

| 测试项 | 方法 | 结果 |
| ---- | ---- | ---- |
| 图片分析 | 截取 onepeople.mp4 一帧调用接口 | 成功评分 78，输出反馈 |
| 视频分析 | 150 帧片段 | 识别 4 动作、2 标准、平均 85.8 |
| 视频分析（真实上传） | 391 帧训练视频重跑 | 9 动作、平均 87.9、最高 96.4 |
| 实时分析 | 90 帧模拟摄像头输入 | 4 动作、平均 85.6、录像可读 |
| 标准动作库 | 新建 / 修改 / 删除接口 | 全部通过 |
| 报表统计 | overview / student 接口 | 数据正确 |
| 前端交互 | 内嵌 JS 语法检查 + 浏览器操作 | 通过（修复过 async 关键字问题） |

### 3. 质量保障手段

- `python -m py_compile` 语法检查；
- Node `--check` 检查前端脚本；
- 接口冒烟测试（health / standards / analyze / reports）；
- 分析结果用 OpenCV 校验帧数、可读性；
- 关键数据写入前统一走 `storage.py`，避免 SQL 散落在业务代码中。

## 四、用户体验优化

| 问题 | 优化措施 |
| ---- | ---- |
| 视频结果无法播放 | 输出改为 WebM，浏览器原生支持 |
| 生成速度慢 | VP8 编码 + 输出宽度限制 960 |
| 没有统计数据 | 增加平均分、最高分、动作数、标准数 |
| 缺可视化 | 增加逐帧评分曲线 Canvas 图 |
| 实时画面卡顿 | 发送—响应背压，后端慢时自动丢帧 |
| 实时无记录 | 停止自动保存录像与训练记录 |
| 刷新后角色丢失 | localStorage 恢复用户与角色 |
| 学生看不懂术语 | 输出自然语言中文建议 |
| 教练改参数困难 | 标准库 UI + JSON 参数编辑 + 关键帧标注 |
