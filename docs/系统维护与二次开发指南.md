## 一、维护总览

### 1. 目录与职责

| 路径 | 职责 | 修改风险 |
| ---- | ---- | ---- |
| `main.py` | API 路由、WebSocket、静态资源 | 中 |
| `analysis_service.py` | 视频/图片/实时分析的业务编排 | 中 |
| `storage.py` | SQLite 表结构、CRUD、默认标准参数 | 高（涉及数据） |
| `analyzer.py` | 动作区间状态机、排球追踪、动作计数 | 高（影响统计） |
| `pose_judge.py` | 评分规则、阈值、反馈文案 | 高（影响评分） |
| `body.py` | 姿态推理与可视化 | 中 |
| `volleyball_detect.py` | 排球检测封装 | 低 |
| `index.html` / `extra_features.js` | 前端界面与交互 | 中 |
| `data/volleyball.db` | 运行数据 | 极高（必须备份） |
| `results/` | 生成的评分视频/图片 | 低（可删） |

### 2. 正确的操作环境

```bat
conda activate volleyball_analytics
cd /d C:\Projects1\volleyball_system_v2
```

查看当前服务是否在运行：

```powershell
Get-NetTCPConnection -LocalPort 8000 -State Listen
```

停止服务：

```powershell
Get-Process python | Where-Object { $_.Path -like "*volleyball_analytics*" } | Stop-Process -Force
```

## 二、日常维护

### 1. 数据库备份（最重要）

服务停止后，直接复制文件即可：

```bat
copy data\volleyball.db data\volleyball_backup_20260912.db
```

恢复：把备份文件改名为 `volleyball.db` 覆盖回去。

### 2. 清理结果视频

`results\videos`、`results\images` 可以随时删除，不影响系统运行；`data\uploads` 是原始训练视频，删除会失去历史记录对应的源文件。

### 3. 日志

- `server.out.log`：请求记录、模型推理输出；
- `server.err.log`：启动错误堆栈；
- 排查问题时先看这两个文件。

## 三、Bug 修复标准流程

### 第 1 步：复现问题

记录：哪个页面、哪个按钮、什么操作、期望结果、实际结果。
例如：“学生上传 10 秒视频，点开始分析，返回 500”。

### 第 2 步：看日志

```powershell
Get-Content server.err.log -Tail 50
Get-Content server.out.log -Tail 80
```

在日志里找到第一个 `Traceback`，最后一行通常是根因。

### 第 3 步：定位代码

- 接口报错 → `main.py`；
- 分析流程报错 → `analysis_service.py`；
- 数据写入报错 → `storage.py`；
- 评分/计数异常 → `pose_judge.py` / `analyzer.py`；
- 页面点击无响应 → 浏览器 F12 Console，多半是 `index.html` 或 `extra_features.js` 的 JS 错误。

### 第 4 步：修改代码

- 只改必要的行，保持现有风格；
- 修改前先复制一份 `.bak` 或提交 git；
- 前端脚本改完必须做语法检查。

### 第 5 步：验证

```bat
python -m py_compile main.py analysis_service.py storage.py analyzer.py pose_judge.py
```

前端 JS 检查（可选，需要 Node）：

```bat
node --check extra_features.js
```

接口冒烟测试：

```powershell
Invoke-RestMethod "http://127.0.0.1:8000/api/health"
Invoke-RestMethod "http://127.0.0.1:8000/api/standards"
```

### 第 6 步：重启服务

代码改完后必须重启（FastAPI 没有开自动重载）：

```bat
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

## 四、参数修改与微调

### 1. 推荐方式：在网页里改标准动作参数

教练端 → 标准动作库管理 → 编辑 → 修改参数 JSON → 保存。
这种方式立即生效，不需要改代码、不需要重启。

| 参数 | 含义 | 建议范围 |
| ---- | ---- | ---- |
| `left_elbow` / `right_elbow` | 肘部角度标准区间 | 垫球 160–180，传球 70–140 |
| `left_knee` / `right_knee` | 膝盖角度标准区间 | 垫球 100–150 |
| `hip_height_ratio` | 髋部高度/身高比例 | 0.3–0.7 |
| `right_wrist_shoulder` | 手腕高度/肩部高度 | < 1.05 表示手腕更高 |
| `weights` | 各特征权重，和应为 1 | 按动作调整 |

### 2. 修改系统默认参数

文件：`storage.py` → `DEFAULT_CRITERIA`
作用：新建数据库时写入的默认标准；已经存在的数据库不会自动更新。
适用：重新部署、重置系统时使用。

### 3. 修改代码内置评分阈值

文件：`pose_judge.py` → `ACTION_CRITERIA`
作用：当数据库里没有对应标准时使用的兜底参数。
修改后需要重启服务。

### 4. 修改动作计数灵敏度

文件：`analyzer.py` → `ActionSession`

| 参数 | 当前值 | 作用 | 调大效果 |
| ---- | ---- | ---- | ---- |
| `entry_threshold_multiplier` | 1.3 | 进入动作的球-手距离阈值（×身高） | 更容易进入区间，计数可能变多 |
| `rebound_threshold_multiplier` | 0.5 | 折返判定阈值 | 更容易判定为有效动作 |
| `volleyball_patience` | 5 | 排球丢失容忍帧数 | 轨迹更连续，可能引入误检 |
| 最小有效帧数 | 4 | 区间达到 4 帧即计一次 | 调大更严格，调小更灵敏 |

### 5. 修改检测置信度

| 文件 | 参数 | 当前值 | 说明 |
| ---- | ---- | ---- | ---- |
| `body.py` | `extract_valid_keypoints(confidence_threshold=0.3)` | 0.3 | 调低可检测更多关键点，但噪声增加 |
| `volleyball_detect.py` | `detect_volleyball(model, frame, conf=0.5)` | 0.5 | 调低可捕捉更模糊的球，但误检增加 |

### 6. 实时分析性能参数

| 位置 | 参数 | 当前值 | 作用 |
| ---- | ---- | ---- | ---- |
| `index.html` | 抽帧间隔 | 110 ms | 约 9 FPS，调小更流畅但更吃 CPU |
| `index.html` | Canvas 尺寸 | 640×480 | 上传帧分辨率 |
| `index.html` | JPEG 质量 | 0.6 | 数值越大越清晰、传输越大 |
| `analysis_service.py` | 录像宽度上限 | 960 | 影响生成速度与清晰度 |
| `analysis_service.py` | 录像帧率 | 15.0 | WebM 写入帧率 |

## 五、模型微调（重新训练）

### 1. 数据准备

- 姿态模型：标注人体关键点（建议 12 个核心点：肩、肘、腕、髋、膝、踝左右）；
- 排球检测：标注排球边界框；
- 目录结构示例：

```text
dataset/
├── images/
│   ├── train/
│   └── val/
├── labels/
│   ├── train/
│   └── val/
└── data.yaml
```

### 2. 姿态模型训练

```bat
yolo pose train model=yolov8n-pose.pt data=data.yaml epochs=100 imgsz=640 batch=8
```

评估指标：

- mAP50 / mAP50-95：整体关键点检测质量；
- PCK / 关键点可见率：关节定位准确率；
- 关注肘、膝、腕、踝等对评分最敏感的点。

训练完成后：

```bat
copy runs\pose\train\weights\best.pt pose_best.pt
```

### 3. 排球检测模型训练

```bat
yolo detect train model=yolov8n.pt data=volleyball.yaml epochs=100 imgsz=640 batch=8
copy runs\detect\train\weights\best.pt best.pt
```

### 4. 更换模型后的验证

1. 备份旧权重：`copy pose_best.pt pose_best_old.pt`；
2. 替换新权重；
3. 用 `onepeople.mp4` 重新跑图片 + 视频 + 实时三条链路；
4. 检查关键点是否稳定、排球是否连续、评分是否合理；
5. 若效果变差，用备份回滚。

### 5. 训练加速

- 有 NVIDIA 显卡时安装 CUDA 版 PyTorch；
- 降低 `imgsz`（如 480）或减小 batch；
- 先用小数据集验证流程，再全量训练。

## 六、新增一个动作类型（例如“拦网 block”）

必须同步修改 5 个位置，缺一不可：

1. `storage.py` → `ACTION_LABELS` 增加 `"block": "拦网"`；
2. `storage.py` → `DEFAULT_CRITERIA` 增加该动作的默认阈值与权重；
3. `pose_judge.py` → `ACTION_CRITERIA` 增加阈值；
4. `pose_judge.py` → `judge_pose()` 增加评分分支，`generate_feedback()` 增加反馈文案；
5. `index.html` → `const ACTION = {...}` 增加选项。

改完后：

```bat
python -m py_compile storage.py pose_judge.py
```

重启服务，新建训练验证。

## 九、排错速查

| 现象 | 原因 | 处理 |
| ---- | ---- | ---- |
| 拒绝连接 | 服务未启动 | 运行 uvicorn / 启动系统.bat |
| 点击无响应 | 前端 JS 报错 | F12 Console 查看，修 index.html 后 Ctrl+F5 |
| 视频无法播放 | 旧 mp4 编码 | 重新分析生成 WebM |
| 统计为 0 | 未检测到有效动作区间 | 检查光照/人物/排球，调阈值 |
| 端口占用 | 8000 已被使用 | 换 8001 或结束占用进程 |
| 模型缺失 | 权重文件被移走 | 放回 pose_best.pt / best.pt |
| 内存不足 | 视频过长/分辨率过高 | 剪短视频或提高硬件 |

## 十三、维护封存流程（防止多人访问导致数据错乱）

### 方式一：维护模式（推荐，不断开服务）

1. 教练账号登录网页；
2. 点击右上角“进入维护模式”；
3. 其他用户的所有分析、写入请求会收到 503“系统维护中”，实时分析连接会被拒绝；
4. 健康检查、登录、修改密码、维护开关仍然可用，方便管理员操作；
5. 修改完成、验证通过后，点击“退出维护模式”。

维护模式的标志文件：`data/maintenance.lock`（存在即维护中，删除即恢复）。

### 方式二：完全停机（改数据库/改依赖时使用）

1. 双击 `停止系统.bat`，或回到运行窗口按 Ctrl+C；
2. 期间任何人都无法访问系统，最安全；
3. 修改完成后用 `启动系统_局域网.bat` 重新启动。

### 修改前必须备份数据库

- 双击 `备份数据库.bat`；
- 备份文件保存到 `data/backups/volleyball_日期_时间.db`；
- 备份使用 SQLite 官方 backup API，**服务运行中也可以安全备份**；
- 恢复方法：停服后把备份文件复制为 `data/volleyball.db`。

### 推荐的发布流程

```text
通知使用者 → 进入维护模式 / 停止服务
→ 备份数据库
→ 在开发副本修改代码
→ python -m py_compile 检查
→ 重启服务
→ 冒烟测试（health / 登录 / 分析一条）
→ 退出维护模式
→ 通知使用者恢复使用
```

### 开发与生产分离（强烈建议）

- 生产目录：`C:\Projects1\volleyball_system_v2`（局域网用户使用）；
- 开发目录：复制一份为 `volleyball_system_v2_dev`，用 8001 端口测试；
- 测试通过后再同步到生产目录，避免边改边崩影响使用者。

```bat
python -m uvicorn main:app --host 127.0.0.1 --port 8001
```

### 多实例注意事项

- 同一时间只允许一个服务进程占用 8000 端口；
- 不要在多个端口启动多个服务同时写同一个 `data/volleyball.db`；
- SQLite 已启用 WAL 模式，读操作并发安全；分析请求由服务内部锁串行执行；
- 维护模式下仍请避免手动删除数据库文件，先备份再操作。
