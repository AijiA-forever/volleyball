## 第一部分：先放下焦虑——大创的创新不等于发明新算法

很多同学误以为“创新 = 提出一个新的神经网络”。实际上，本科创新训练项目的创新通常有四类，难度从低到高：

| 创新类型 | 含义 | 难度 | 适合你的程度 |
| ---- | ---- | ---- | ---- |
| 应用创新 | 把已有算法用到一个没人做好的具体场景 | 低 | ★★★★★ |
| 工程创新 | 把算法做成能装、能跑、能用的产品 | 低 | ★★★★★ |
| 数据创新 | 自建贴合场景的数据集并验证 | 中 | ★★★★ |
| 评估创新 | 用科学指标证明系统真的有用 | 中 | ★★★★ |
| 算法创新 | 改进网络结构、提出新模块 | 高 | ★（不建议现阶段） |

**你的最佳策略：把已有的检测 + 姿态 + 评分系统，做成“能落地、可测量、有数据”的教学产品，并用实验证明它有效。**

这本身就是创新，而且比硬凹一个新模块更扎实。

## 第二部分：用大白话理解你现在的系统

不要一上来读论文。先理解这条链路：

```text
一段训练视频
  → 拆成一帧一帧图片           （OpenCV）
  → 在每一帧里找出人、球        （目标检测 YOLO）
  → 在每个人身上找出关节位置    （姿态估计 Pose Estimation）
  → 用关节位置算角度            （几何/余弦定理）
  → 和标准参数比较              （规则引擎）
  → 给分数和中文建议            （评分与反馈）
  → 存进数据库、出报表          （SQLite + 前端）
```

对应到生活中的比喻：

- **目标检测**：像在照片上圈出“球在哪、人在哪”；
- **骨架提取（姿态估计）**：像在人的身上点出肩、肘、腕、膝这些点，再用线连起来；
- **关键点**：就是这些关节点的坐标 (x, y)；
- **置信度**：模型对这个点有多确定（0~1，越高越可信）；
- **评分**：把角度和标准区间比大小，落在区间里得高分；
- **动作计数**：球靠近人、再离开，中间那一小段时间就算一次动作；
- **实时分析**：把上面整套流程压缩到每一秒钟连续做，画面延迟刷新。

**把这张图背下来、讲给同学听，你对系统的理解就超过大多数人了。**

## 第三部分：最小知识地图（够用即可）

不需要成为专家，先掌握这些“够用”的知识：

### 1. Python（够改代码）

- 变量、列表、字典：用来存检测结果和参数；
- `for` / `if`：用来遍历帧、判断条件；
- 函数 `def`：把一段逻辑封装起来；
- 类 `class`：本项目的 `AnalysisService`、`ActionSession` 都是类；
- `import`：使用别人的库；
- `try/except`：错误处理；
- 文件读写：`open`、`json`。

### 2. OpenCV（够处理视频）

- 一张图片在计算机里就是一个数字矩阵；
- `cv2.VideoCapture` 读视频，`cap.read()` 读一帧；
- `cv2.resize` 缩放，`cv2.rectangle` 画框，`cv2.putText` 写字；
- BGR 通道顺序、宽高 `(w, h)`。

### 3. 目标检测与姿态估计（够读懂论文图表）

- 检测（Detection）：输出边界框 `[x1, y1, x2, y2]` 和类别；
- 姿态（Pose）：输出关键点 `(x, y, conf)`；
- IoU：两个框重叠程度的指标；
- NMS：去掉重复框；
- mAP：检测精度的常用指标；
- FPS：每秒处理帧数，实时性的指标；
- 微调（Fine-tune）：用自己数据继续训练已有模型。

### 4. Web 与数据库（够维护系统）

- HTTP 接口：前端用 `fetch` 把视频发给后端；
- WebSocket：实时分析用的双向长连接；
- SQLite：一个文件就是数据库，存训练记录和标准动作；
- 表、主键、外键、增删改查。

### 30 分钟读一篇论文的方法

1. 读标题 + 摘要 + 结论（5 分钟）：解决什么问题、达到什么效果；
2. 看所有图表和实验结果（10 分钟）：用了什么数据、指标多少；
3. 看方法结构图（10 分钟）：输入是什么、输出是什么、加了什么模块；
4. 记录“可借鉴点”和“不足”（5 分钟）。

**不要逐字翻译论文，那是效率最低的做法。**

## 第五部分：创新点菜单（按可落地程度排序）

### 推荐组合（最适合你）

**创新点 1：个性化训练档案与进步趋势分析**
- 现状：系统只存单次训练分数；
- 改进：按学生、按动作、按关节（膝角/肘角）统计历史趋势，画进步曲线；
- 改动：`storage.py` 加查询、`main.py` 加趋势接口、`index.html` 画折线；
- 可写：从“一次性打分”升级为“长期教学追踪”。

**创新点 2：系统评分与教练评分的一致性校准**
- 现状：评分阈值是人为设定的，没证明和教练判断一致；
- 改进：请教练给 20–30 段视频打分（1–10 分或标准/不标准），计算系统分与教练分的相关系数（Pearson/Spearman），再网格搜索调整权重，使一致性最好；
- 改动：只需要改标准动作参数 + 写一个分析脚本，几乎不用动核心算法；
- 可写：这是最有说服力的创新——用数据证明系统“像教练一样打分”。

**创新点 3：教学场景轻量化实时优化**
- 现状：实时性靠经验；
- 改进：测试不同分辨率、抽帧间隔、模型大小下的 FPS 与延迟，提出自适应策略（画面复杂时降分辨率，简单时升分辨率）；
- 改动：只改几个参数 + 写实验脚本 + 画性能曲线；
- 可写：面向普通笔记本落地的工程创新。

**创新点 4：反馈的严重程度分级与训练建议推荐**
- 现状：反馈是固定句子；
- 改进：按偏差大小分“轻度/中度/重度”，并关联对应练习动作（如“膝角不足 → 半蹲练习”）；
- 改动：`pose_judge.py` 反馈逻辑 + 一张建议表；
- 可写：从“诊断”升级为“教学处方”。

### 其他可选项

| 创新方向 | 一句话说明 | 难度 |
| ---- | ---- | ---- |
| 多标准分级评价 | 为初学者/进阶者设不同标准 | 低 |
| 关键帧时序对比 | 用 DTW 比较学生与标准动作的时间序列 | 中 |
| 双视角几何校正 | 用单应矩阵修正透视导致的关节角度偏差 | 中高 |
| 多人同时分析 | 加入跟踪 ID，区分不同学生 | 中高 |
| 可解释性可视化 | 高亮偏差最大的关节、画偏差热力图 | 中 |
| 半自动标注 | 模型预标注 + 人工修正，快速建数据集 | 中 |
| 课堂大屏模式 | 教练端批量排队分析、投屏展示 | 低 |

**建议的组合叙事（结题很好写）：**
“本项目的创新在于：① 把姿态估计与排球教学标准结合，实现可解释的动作评分；② 通过教练评分一致性实验校准了评分参数；③ 面向普通笔记本实现了轻量化实时分析与训练档案闭环。”

## 第七部分：手把手示例——如何加一个“膝角趋势图”

这是最适合作为第一个改造练手的任务：

1. 理解数据：`session_attempts.details_json` 里已经保存了每次动作的关节角度；
2. 后端 `storage.py` 增加查询：按学生取出所有 session 的平均膝角；
3. `main.py` 增加接口 `/api/reports/trend/{student}`；
4. `index.html` 在报表页画一条折线；
5. 验证：用现有的训练记录就能出图。

做完这个，你就完成了“数据库 → 接口 → 前端可视化”的全链路改造，对系统的理解会彻底不一样。

## 第八部分：必须避开的坑

1. **不要伪造数据或准确率**：大创评审专家很容易识破；
2. **不要一开始就改网络结构**：改了也说不清为什么；
3. **不要只做界面**：要有可测量的实验；
4. **不要堆砌名词**：能用一句大白话解释才算真懂；
5. **不要丢掉可复现性**：每次实验记录参数、数据、结果。

## 第九部分：一句话总结你的创新策略

> 不发明新模型，而是：**用现成算法解决真实教学问题，用自建数据证明有效，用工程手段让它跑得动、用得好。**

做到这三点，就是一个完整、可信、有落地价值的大创项目。
