## 一、这条线要解决什么问题

系统原本只有**逐帧规则评分**：`pose_judge.py` 用角度阈值（如垫球肘角 160–180°、膝角 100–150°）逐帧打分，`ActionSession` 把区间内各帧分数取平均。

项目文档诊断出的**头号缺陷**是"评分标准没有效度证据"——阈值和权重全是人工经验值，从未与教练判断比对过，所以"评分准不准"这个问题目前无法回答。

时序建模这条线的目标是四件事：

1. **补效度证据**：让系统分与教练评分做一致性实验（结题/论文必需）
2. **增加新维度**：现有评分只有逐帧快照，说不出"节奏拖沓""动作不连贯"
3. **加固基础设施**：动作分区与计数目前完全依赖排球轨迹，很脆弱
4. **增值标准动作库**：从"只能看"变成"可以比"

一致性实验是**验证手段**，不是最终目的。

## 三、核心设计与参数（重跑成本高，先看这里）

### 3.1 特征（10 维，`temporal.py`）

```
left_elbow_angle, right_elbow_angle,
left_knee_angle, right_knee_angle,
left_hip_angle, right_hip_angle,
trunk_inclination,
platform_tilt,          # 前臂平台倾角，按 180° 取模折到 [0,90]
hip_y_rel,              # 髋相对踝中点，除以身高
wrist_y_rel             # 腕相对踝中点，除以身高
```

距离计算前各维缩放：角度 /90、位置 /0.25（统一量级）。

### 3.2 DTW

- 多维 DTW，代价为缩放后特征的欧氏距离
- Sakoe–Chiba 弯曲带：`band = max(|n−m|, 0.25 × max(n,m))`
- 距离归一化：累计代价 ÷ (n+m)
- 相似度 = `100 × exp(−距离 / tau)`，**`tau` 默认 1.0，尚未用教练评分校准**
- 回溯对齐路径 → 逐维平均绝对偏差（输出"偏差最大项"，可定位到具体关节）

### 3.3 算法自检基准（`python temporal.py --self-test`）

| 场景 | 相似度 |
| --- | --- |
| 完全相同的序列 | 100.0 |
| 时间拉伸 1.7 倍 | 100.0（DTW 吸收时间错位） |
| 3° 噪声 | 95.1 |
| 屈膝差 15° | 88.9 |
| 屈膝差 30° | 79.0 |

**注意**：DTW 按设计会吸收时间错位，所以"节奏"不体现在相似度里，只能从**时长比**看。

### 3.4 模板构建

- 从目录内所有视频采集动作区间 → 每段转 10 维矩阵
- 取 **medoid**（到其余样本 DTW 距离之和最小的一条）作为模板
- 存为 `.npz`（`matrix` / `feature_keys` / `action_type` / `meta`），约 8 KB
- `meta` 记录：参与动作数、来源视频名、medoid 索引、各样本距离和、**推理配置**

**模板是"某一条真实片段"，不是多段视频的平均。**

### 3.5 当前使用的推理配置

`pose_imgsz=640, pose_conf=0.3, ball_imgsz=640, ball_conf=0.5`（写入模板 meta）

## 四、实测数据与关键结论

### 4.1 六段教练视频的基本情况

| 视频 | 分辨率 | 帧率 | 帧数 | 真实球检出 | 外推补位 | 完全无球 |
| --- | --- | --- | --- | --- | --- | --- |
| 01 | 478×854 | 30 | 230 | 145 | 57 | 28 |
| 02 | 480×852 | 30 | 430 | 380 | 30 | 20 |
| 03 | 480×852 | 30 | 198 | 197 | 1 | 0 |
| 04 | 592×1280 | 30 | 471 | 470 | 1 | 0 |
| 05 | 1280×720 | 30 | 562 | 554 | 6 | 2 |
| 06 | 592×1280 | **18** | 71 | 71 | 0 | 0 |

球检测率都不低，但**分辨率、帧率、机位都不统一**（4 段竖屏、1 段横屏）。

### 4.2 球-手臂距离分布（倍身高，进入阈值 = 1.30）

| 视频 | 最小 | 25% | 中位 | 75% | 95% | 最大 |
| --- | --- | --- | --- | --- | --- | --- |
| 01 | 0.01 | 0.46 | 0.92 | 1.01 | 1.27 | 2.49 |
| 02 | 0.00 | 0.38 | 0.85 | 1.29 | 1.63 | 1.92 |
| 03 | 0.15 | 0.78 | 1.14 | 1.65 | 2.86 | 2.97 |
| **04** | 0.03 | 0.46 | **0.77** | 0.99 | **1.19** | 1.41 |
| 05 | 0.08 | 0.64 | 1.00 | 1.22 | 1.60 | 1.95 |
| **06** | 0.02 | 0.99 | **1.33** | 1.57 | 1.88 | 1.91 |

**结论：同一个绝对阈值不可能同时适配这六段。** 04 的 95% 分位（1.19）低于阈值 → 状态机永不退出（实测一个 408 帧的区间）；06 的中位数（1.33）高于阈值 → 难以触发（只有 1 条超过 8 帧）。

### 4.3 切分的根本问题：状态 vs 事件

现有 `ActionSession` 用"状态是否成立"划分区间：

```
进入：球-手臂距离 < 1.3×身高  且  球在手腕上方
退出：上述条件不再满足
```

**"球在手臂附近"是状态，可以持续任意长时间；动作边界必须由事件定义。** 这是 04/05 号出现 408/221 帧区间的根本原因（实测区间内球-臂距离中位仅为阈值的 0.58/0.67 倍、100% 帧球在腕上）。

**建议方向**：改用**触球事件**——对距离序列做中值滤波后取局部极小值（配最小间隔约束），每个触球时刻前后取固定时间窗定义动作区间。一次解决四个问题：区间长度恒定、不依赖状态退出、触球帧天然成为相位锚点、动作计数可解释。

### 4.4 相似度的可重复性（关键结论）

用**同一个人的视频**建模板、再比同一个人的其他动作（26 个动作）：**平均 66.0**

用现有模板（来自 06 号视频）比所有人（33 个动作）：**平均 65.2**

| 视频 | 教练内部自比 | 跨教练 |
| --- | --- | --- |
| 01 | 68.0 | 69.0 |
| 02 | 62.1 | 63.2 |
| 03 | 63.9 | 63.5 |
| 05 | 77.5 | 60.5 |

**两者几乎相同 → "跨教练风格差异"不是主因**，`64~66` 分主要来自同一人重复动作之间的差异，即**切分噪音 + 测量噪音**。

含义：当前管线的**可重复性上限约 66 分**，任何小于这个幅度的分数差都不可信。这是继续做一致性实验前最需要改善的地方。

### 4.5 推理配置必须一致

同一段视频（06 号）对自己的模板：

- 建模板与对比都用 640 → **100 分**
- 建模板 640、对比 320 → **64.9 分**

所以模板 meta 里记录了推理配置，不一致时会告警。**跑一致性实验时，所有视频必须使用同一套配置。**

### 4.6 无球视频完全不可用

画面里没有球 → 状态机不启动 → 采集 0 个动作区间 → 建模板失败（已改为可读提示）。

### 4.7 归一化基准的实证（推翻了"用肢体长度"的设想）

各基准量在视频内的变异系数 CV：

| 基准量 | CV |
| --- | --- |
| 肩-踝垂直距（现用） | **3.9% ~ 13.8%** |
| 上臂长 | 9.2% ~ 26.6% |
| 前臂长 | 9.2% ~ 32.9% |
| 大腿长 | 5.8% ~ 14.5% |

肢体长度因 2D 投影缩短 + 短线段噪声占比大，**反而更不稳定**。身高仍是更好的基准。

## 五、待办事项（按优先级）

### P0：提高可重复性（当前最大瓶颈）

1. **触球事件化分区**（上一节 4.3）：预计是提升最大的单项改动
2. **距离序列中值滤波去尖峰**：01 号有多次跳到 2.5~3.0 的检测异常，会制造假极小值
3. **位置维度改用整段中位身高归一化**：`metrics.py` 已用整段中位身高（避免下蹲时虚高），但 `temporal.py` 仍用逐帧身高，两者不一致。改动后需重建模板。
4. **统一拍摄条件**：同一机位、同一侧身、同一分辨率与距离

### P1：一致性实验（结题必需）

5. **挑一位教练建参考模板**（现在这份是六位教练混合，medoid 只代表"最典型的一条"而非"标准"）
6. **拍 20–30 段学生垫球视频** + 2 名教练独立打分（格式见 `tools/coach_rating_template.csv`）
7. **跑双通道一致性实验**，得到"阈值通道 vs 时序通道"与教练评分的相关性

### P2：设计改进

8. **模板集合 + 最近邻匹配**：用多条不同风格的模板，学生取"与最近模板的相似度"。可缓解"动作标准但习惯不同被误判"的问题。现有六位不同教练的视频正好是风格集合的雏形。
9. **左右侧身/机位一致性校验**：目前只校验动作类型，不校验机位与侧身
10. **接入 Web 界面**：时序通道目前只有命令行，未进入学生端

### 常用命令

```bat
:: 算法自检（不需要模型与视频）
python temporal.py --self-test

:: 建模板
python temporal.py --build-template --videos "data\templates_src\dig_side" --action dig ^
    --out data\templates\dig_side.npz --min-frames 8

:: 单个视频对比
python temporal.py --video "data\eval_videos\dig_side\dig_S01_side_01.mp4" ^
    --template data\templates\dig_side.npz

:: 双通道一致性实验
python tools\validate_metrics.py --videos "data\eval_videos\dig_side" ^
    --ratings "data\eval_videos\ratings.csv" --action dig ^
    --dtw-template data\templates\dig_side.npz --min-frames 8

:: 球-手臂距离诊断图
python tools\plot_ball_distance.py
```

### 关键参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--min-frames` | 4（对比路径常设 8） | 区间最少帧数 |
| `--max-len-ratio` | 3.0 | 区间长度上限（相对中位帧数的倍数），0=关闭 |
| `--tau` | 1.0 | 相似度映射尺度，**待用教练评分校准** |
| `--band-ratio` | 0.25 | DTW 弯曲带宽度 |
| `--dtw-template` | 无 | 提供后启用双通道对比 |

## 八、避坑清单

1. **建模板与对比必须用同一套推理配置**（`VB_POSE_IMGSZ` / `VB_BALL_IMGSZ` / 两个置信度阈值），否则相似度会静默偏低（实测 100 → 64.9）
2. **无球视频切不出任何动作**——现有切分依赖排球轨迹
3. **`--videos` 传目录且目录内不能混不同动作/机位**，否则模板会被混建
4. **DTW 吸收时间错位**，节奏差异只能看"时长比"，不在相似度里
5. **`tau=1.0` 未校准**，绝对分数的含义有限，目前看排序（Spearman）比看绝对值更有意义
6. **`templates/` 不在 `.gitignore`**，模板建议放在 `data/templates/`（已被忽略），否则会出现在 git status
7. **前端上传会丢失文件名**（改成 UUID），做一致性实验要用独立目录保留原始文件名
8. **不要用学生视频建模板**，否则基准降到平均水平
9. **各视频的内部自一致性差异明显**：05 号 77.5、01 号 68.0、03 号 63.9、02 号 62.1。选参考模板时可把"可重复性高"作为参考指标之一，但"是否最标准"仍需人工判断（建议请另一位教练确认）
